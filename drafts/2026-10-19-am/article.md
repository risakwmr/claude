# 社内の資料、生成AIに入れていい？ ― 迷ったときの3つの切り分けと聞き方（AIに渡す仕事、渡さない仕事 #06）

> 状態：下書き（要記入7・確認2あり）。シリーズ「AIに渡す仕事、渡さない仕事 #06（仮）」（#05 は下書きが2本あり、番号の最終判断はSenaに）。有料化版（RULES 5.5／5.6 に合わせて作成）。（2026-10-18 校閲の指摘で修正）公開前にこの状態の行ごと削除する。

こんにちは、セナです。

AIに要約してもらおうと思って、資料をコピーする。
貼り付ける直前で、手が止まる。

「これ、AIに入れていいんだっけ」

となるとき。

周りは普通に使っていそうだし、今さら聞くのもちょっと恥ずかしい。
会社が用意したAIと、個人で使っているAIで何が違うのかも、正直よく分からない。
結局、なんとなくの感覚で「たぶん大丈夫」か「やめておこう」を決めている。

そういう、毎回ちょっとだけ迷っている人に向けた記事です。
（この場面は読者の例として書いたもので、私の体験そのものではありません）

この記事で分かること

- 職場で「許されているか分からないまま」AIを使っている人がどのくらいいるか、「入れたら漏れる」の研究はどこまで分かっているか
- 入れるかどうかを自分の感覚で決めないための、3つの切り分け（無料部分）
- 入れる前のチェックリスト、上司や担当部署への聞き方の文例（日本語・英語）、急いでいる日・調子が低い日の分岐（有料部分）

※最初に大事な前提です。社内の情報をAIに入れてよいかは、会社のルールを確認するのが前提です。この記事は会社のルールの代わりにはなりませんし、法律の判断もしません。この記事の提案と会社のルールが食い違うときは、いつでもルールが優先です。

前に「AIに渡す仕事、渡さない仕事 #01」で、AIに渡すかどうかは「間違いに気づけるか」で決める、と書きました。

でも、その前にもう1つ、関門があるんですよね。
そもそも、この情報をAIに入れていいのか。

【✏️要記入：AIに何かを入れる前に、手が止まったことがあるか。あれば、どんな種類の情報のときだったか。（ガイド：「社内の資料」「数字が入ったメール」「人の名前が入った議事録」くらいの粒度で。具体的な中身・社名・ツール名・会社のルールの内容、そのあと入れたか入れなかったかは書かない。なければ「あまり迷ったことがない。でも、それも怖いかもしれない」のような本音でも）】

この「入れていいか」は、研究で答えが出る話ではありません。
ただ、職場で実際に何が起きているかは、少し調べられていました。

## 02｜研究で分かっていること：「分からないまま使う」は少なくない

KPMGとメルボルン大学が、47か国・48,340人に行ったオンライン調査があります（2024年11月〜2025年1月）。
大学の研究チームが設計した大きな調査ですが、査読を受けた論文ではなく、調査報告です。

職場でAIを使っている人（47か国全体）のうち、

- 「許されているか分からないまま、職場でAIツールを使った」：56%
- 「会社の情報（財務・営業・顧客情報など）を公開AIツールにアップロードした」：48%

と答えていました。

ここは誤解しやすいので、先に断っておきます。
この割合は「少なくとも一度はある」という意味で、「まれに（Rarely）」と答えた人も含まれています。
「半分の人が日常的に会社の情報を入れている」という意味ではありません。
「会社の情報」がどのくらい機密のものかも、この調査では分かりません。

もう1つ。
同じ調査で、勤め先に生成AIの方針やガイダンスがあると答えた人は、禁止の方針も含めて約4割。
19%は、方針があるかどうか「分からない」と答えていました（こちらは、誰を分母にした値かが報告書に明記されていません）。

どれも本人の申告で、実際の行動を見たものではありません。
報告書自身も、言いにくい行動なので少なめに出ている可能性がある、と書いています。
（日本の数字は、有料部分の12にまとめました）

### 聞きにくさも、あるのかもしれない

もう1つ、気になった研究があります。

オンラインで行われた4つの実験（合計4,439人、PNAS）で、仕事でAIを使う人は「能力ややる気を低く見られる」と予想していて、実際にそう評価されていました。
1つ目の実験では、AIツールを使う場面を想像した人のほうが、そうでないツールの場面の人より、上司や同僚に使ったことを伝えたがらない傾向がありました。

これは「使ったことを伝えるか」の実験で、「ルールを聞くか」を調べたものではありません。
なので、ここからは推測です。
「AI使ってるって言いにくい」が、「これ入れていいですか、と聞きにくい」の背景の1つになっているのかもしれません。

（人がルールを確かめずに使う理由を、直接調べた査読済みの研究は、今回は見つかりませんでした）

## 03｜「入れたら漏れる」は、どこまで分かっているか

ここで、不安になりすぎないために、技術の研究も少しだけ。

大規模言語モデル（ChatGPTのようなAIの中身）は、学習に使われた文章の一部をそのまま覚えていて、条件がそろうと出してしまうことがある。
これは研究で確かめられています。

- 古いモデル（GPT-2）から、学習データの文章を数百件、一字一句そのまま取り出せた研究がある（Carlini ほか, 2021）
- 一般向けの対話型AI（ChatGPTを含む）からも、数千件の学習データを取り出せた研究がある（Nasr ほか, 2025）

ただ、ここからが大事なところです。

- これは、研究者が意図的に工夫した入力で「攻撃した場合」の結果です
- 取り出されたのは、主に公開ウェブ由来の学習データで、ほかの利用者がチャットに入力した内容が出てきたわけではありません
- 対象のモデルは古いものが多く、事業者はその後対策をしています
- 「一字一句覚えている」ことと「チャットで漏れる」ことは同じではない、という研究もあります（Sander ほか, 2025）

なので、普段のチャットで入れた内容が、別の人の画面に出てくる確率は、分かっていません。
「入れたら漏れる」とも、「入れても漏れない」とも言えない。

一方で、利用者側の研究では、人と話しているような会話のスタイルが、より踏み込んだ打ち明け話を促していた、という結果もありました（Zhang ほか, 2024。会話データの分析と19人へのインタビュー）。

話しやすいと、つい入れてしまう。
これは誰にでも起きそうです。

もう1つ。
入れたものは、学習に使われるかどうかとは別に、サービス側にしばらく保存されることがあります（期間や扱いは、サービスや契約によって違います）。
なので「学習に使わない設定なら、何を入れても大丈夫」とも言えません。
どのAIで、どういう契約・設定になっているかは変わりやすいところなので、会社が用意した説明や、サービスのページで確認してください。

## 04｜「どの情報ならいいか」は、研究ではなく会社のルールで決まる

じゃあ、国のガイドラインはどうなっているのか。

総務省・経済産業省の「AI事業者ガイドライン（第1.2版、2026年3月）」には、AIを使う側について「機密情報等を不適切に入力することがないよう注意を払う」「個人情報を不適切に入力することがないよう注意を払う」といった項目があります（本編 第5部「AI利用者に関する事項」U-4・U-5）。
個人情報保護委員会も2023年6月に、生成AIサービスに個人情報を入れるときの注意を出しています。

ただ、このガイドラインは罰則のない「ソフトロー」で、宛先は従業員一人ひとりではなく、事業者（会社や、会社の中の部門）です。
別添では、各社が自分たちのAIポリシーや規定に合ったチェックリストを作ることが大事だ、と書かれています。個人情報の扱いについては、社内にプライバシー保護の担当組織を置き、新しい技術を使う部署が悩みを抱え込まずに相談できる体制をつくることが重要だ、とも。

つまり、「この情報は入れてよい／いけない」という具体的な線を国が一律に決めているのではなく、各社が自分たちのポリシーに合わせて決める形になっている。

だから、個人の感覚で決めるより、まず会社のルールを確認する。
当たり前と言えば当たり前なんですが、、、

でも、02のとおり、ルールがあるか分からない人も少なくない。
それで毎回「たぶん大丈夫」を一人で決めることになる。

じゃあ、どうするか。
「自分で決めない」ことを、手順にしてしまう。今回の記事は、その話です。

⸻

## 05｜無料で持ち帰れる軸：3つで切り分ける

ここからは研究の結論ではなく、この記事の提案です。
この切り分けで間違いが減ることを確かめた研究はありません。

入れる前に、次の3つを順番に見ます。

1. 会社のルールはある？（ある／ない・分からない）
2. どのAI？（会社が用意したAI／個人で使っている外部のAI）
3. 何の情報？（もう公開されている／社内限り／顧客・個人・未発表）

1で「分からない」なら、その時点で入れずに、確かめる側に回る。
1で「ある」なら、2と3をルールに照らす。
ルールを読んでも自分の情報がどれに当たるか分からなければ、それも「分からない」として、聞く。

たとえば、

もう社外に公開されている資料の要約を、会社が用意したAIで頼む
→ ルールで認められているなら、迷う場面は少なめ。

まだ発表していない数字が入った資料を、個人で使っているAIに貼る
→ 3つとも慎重な側。ここは入れずに、聞く。

という感じです。
（例は読者向けに作ったもので、私の実際の仕事ではありません）

ポイントは、「入れていいか」を自分で決めるのをやめて、「分からなかったら聞く」までを手順に入れておくこと。
迷うのが悪いのではなくて、迷ったときの行き先を先に決めておく、くらいの感じです。

ひとつだけ、聞かせてください。

AIに入れる前に手が止まるのは、①社内の資料 ②顧客や数字 ③同僚の名前や評価 のどれが多いですか？ コメントで番号だけでも教えてもらえたら嬉しいです。

「AIに渡す仕事、渡さない仕事」は、マガジンにまとめています。
続きを読みたい方は、フォローしてもらえると励みになります。

## 07｜コピー用：AIに入れる前のチェックリスト

以下はこの記事の提案です。
チェックリストで情報の扱いの間違いが減るかを、直接確かめた研究は見つかっていません。

```
AIに入れる前（貼り付ける・アップロードする前）

【1】会社のルール
□ 会社に、生成AIの使い方についてのルールやガイダンスがあるか知っている
□ そのルールの置き場所（社内のページ、研修資料など）が分かる
→ どちらかが「分からない」なら、入れない。08の質問文Aで聞く
→ 「ルールはない」と確認できても、自由に使ってよいとは限らない。
  上司か担当部署に、どう扱えばいいか聞く（質問文B）。
  返事が来るまでは、公開済みの情報だけにする

【2】どのAIか
□ 今使おうとしているのは、会社が用意したAIか、個人で使っている外部のAIか、分かっている
□ そのAIが、ルールで仕事に使ってよいとされているものか分かる
→ 分からないなら、入れない（質問文C）

【3】何の情報か
□ もう社外に公開されている情報だけか
□ 社内限りの情報が入っていないか（資料、議事録、Slackのやり取り）
□ 顧客・取引先の情報が入っていないか
□ 同僚や自分以外の人の名前・評価・健康のことが入っていないか
□ まだ発表していない数字・計画・製品の話が入っていないか
→ 社内限り・顧客・個人・未発表が1つでもあれば、ルールで認められている場合だけ。迷ったら入れない

【最後に】
□ 「たぶん大丈夫」で決めようとしていないか
→ 「たぶん」と思ったら、それは「分からない」に入れる
→ どこかで「分からない」が出たら、その先には進まずに聞く
```

最後の1行が、たぶん一番大事です。
「たぶん大丈夫」は、だいたい「分からない」なんですよね。

このチェックリストは「入れていいか」を決めるものというより、「どこで聞けばいいか」に気づくためのもの、くらいに思ってもらえたら。

## 08｜コピー用：上司・担当部署に聞くときの質問文

以下はこの記事が作った文例です。会社や相手との関係に合わせて変えてください。
コツは、「AI使っていいですか？」と広く聞くより、「このツールに、この種類の情報を入れてよいか」を具体的に聞くこと。広く聞くと、返す側も答えにくいので。

〔 〕の中は自分の状況に置きかえてください。

質問文A：ルールがあるか分からないとき（日本語・上司やチームに）

```
生成AIの使い方について、社内のルールやガイダンスがあれば確認したいです。
どこを見ればよいか、教えていただけますか？
```

質問文B：ルールがない・見つからないとき（日本語・担当部署に）

```
〔資料の要約／メールの下書き〕に生成AIを使いたいと考えています。
社内のルールが見つけられなかったのですが、
〔社内限りの資料／顧客名が入った資料〕を入れてよいか、判断の基準があれば教えてください。
```

質問文C：具体的な情報とツールで聞くとき（日本語）

```
〔会社が用意したAI／個人で契約しているAI〕に、
〔社内向けの議事録／まだ公開していない数字が入った資料〕を入れて、
〔要約／翻訳〕してもよいでしょうか。
だめな場合、名前や数字を伏せれば使ってよいかも確認したいです。
```

英語（Slackで上司やチームに）

```
Quick question — is there a policy or guideline on using generative AI tools at work? Could you point me to where I can find it?
```

```
I'd like to use 〔tool〕 to 〔summarize / translate〕 〔an internal meeting note / a doc that includes customer names〕.
Is that OK under our policy, or should I remove names and numbers first?
```

```
I couldn't find guidance on this, so I wanted to check before using AI: is it OK to put 〔type of information〕 into 〔tool〕?
```

（英語は、もっと自然な言い方がありそうです。相手との距離に合わせて直してください）

聞くのが気まずいときは、「自分が使っていいか」より「チームとしてどう扱うか」の聞き方にすると、少し聞きやすいかもしれません。

【✏️要記入：実際に使っている、または使えそうな聞き方があれば1つ。（ガイド：上の文例をSenaの言い方に直したものでもOK。社内のツール名・部署名・ルールの中身は〔 〕に置きかえる。なければ削除）】

## 09｜名前や数字を伏せる・置き換える手順

最初に。
伏せればAIに入れてよい、という話ではありません。ルールで認められていない情報は、伏せても入れないでください。

そのうえで、ルールの範囲で使うときの提案です。

手順

1. 人の名前 → 〔Aさん〕〔Bさん〕に置き換える
2. 会社名・取引先名 → 〔取引先1〕〔取引先2〕に置き換える
3. 製品名・プロジェクト名 → 〔製品X〕〔プロジェクトY〕に置き換える
4. 数字 → 頼みたいことに数字が要らなければ消す。要るなら〔100〕のような仮の数字にする
5. 日付 → 〔来週〕〔月末〕のように、ぼかす
6. 置き換えたあとに、全文を一度読み返す。読んだ人が「どこの会社の、何の話か」分かってしまわないか

置き換えても入れないほうがよい情報

- 組み合わせると特定できるもの（業界・時期・規模がそろうと、名前を伏せても分かってしまう）
- 人事評価、健康のこと、家族のことなど、その人に関わる話。名前を伏せても、本人が読めば分かることがある
- 契約などで、外に出さないことになっている情報（自分で判断がつかなければ、聞く）
- 自分で「これは出したらまずい」と少しでも感じるもの

AIに頼むときの書き方（例）

```
以下は、名前と数字を置き換えた社内向けのメモです。
〔Aさん〕〔取引先1〕などは仮の名前です。本当の名前を推測しようとしないでください。
このメモを、3行で要約してください。
```

置き換えるのは、ちょっと面倒かもしれません。
でも、その面倒くささが「本当にこれ、AIに頼む必要ある？」を考える時間にもなる気がしています。

## 10｜分岐：急いでいる日・調子が低い日

私はうつで治療中で、100%で働けない日があります（「100%で働けない日の仕事術」に書きました）。
なので、この分岐も入れておきます。

研究で分かっているのは、別の分野の話です。
病院の大きなデータで、勤務が長くなるにつれて、分かっているルール（手指衛生）でも守られにくくなる傾向が報告されています（Dai ほか, 2015）。時間に追われるとセキュリティ行動に悪い影響が出うる、というレビューもあります（Chowdhury ほか, 2019）。
どちらも、オフィスワークやAIへの入力を調べたものではありません。うつや体調の波のある「調子が低い日」を調べたものでもありません。（数字は12にまとめました）

そのうえでの、この記事の提案です（目安で、研究が示したものではありません）。

- 急いでいる日 → 07を全部見ようとせず、【1】ルールと【2】どのAIかだけ見る。どちらかが分からなければ、今日はAIに入れずに自分でやるか、後回しにする

## 11｜入れてしまったと気づいたら

ここは法律の判断ではなく、気づいたあとの動き方の提案です。会社に決まった手順があれば、そちらに従ってください。

1. それ以上、入れない（続けて同じ会話に貼らない）
2. 何を・いつ・どのAIに入れたかを、自分用にメモする（入れた情報そのものを、別の場所にまたコピーしない）
3. 会話の履歴を消すかどうかは、自分で決める前に聞く（消してよいか、残しておくべきかは会社の手順による）
4. 上司か、会社の情報管理の窓口に、早めに伝える。窓口が分からなければ、まず上司に
5. 一人で「たぶん大丈夫だった」と片付けない

一人で抱えないこと。
ここが、この節で一番伝えたいところです。

一報の文例（日本語・上司や窓口に）

```
ご相談です。
本日〔時間〕ごろ、〔AIツールの種類：会社のAI／個人のAI〕に、
〔情報の種類：社内向けの資料の一部／顧客名を含むメモ〕を入力してしまいました。
入力したのは〔範囲：1ページ分／数行〕です。
このあとどう対応すればよいか、指示をいただけますか。
```

英語（Slackで）

```
Hi 〔Name〕, I need to flag something.
Earlier today I put 〔type of information〕 into 〔type of AI tool〕 by mistake.
It was about 〔scope〕. What should I do next?
```

気づいて言えるのは、むしろちゃんとしている側だと思います。
言い訳を長くするより、何を・どこに・どのくらい、を先に伝えるほうが、相手も動きやすいはずです。

## 12｜研究で分かっていること・分かっていないこと

### 分かっていること

本文の02〜04・10で書いたことに加えて、細かい数字と、本文で触れなかったものをまとめます。

- KPMG・メルボルン大学の調査（47か国、2024年11月〜2025年1月、査読なし）の数字は、どれも職場でAIを使っている人が分母で、「まれに」を含む。たとえば「会社の情報を公開AIツールにアップロードした」48%は、「まれに」14%と「ときどき〜とてもよく」34%の合計。同じ調査で「方針・ガイドラインに反する使い方をした」は44%
- 日本版の資料では「方針やガイドラインに反する使い方をした」37%。ただし日本版には分母や集計のしかたが書かれておらず、全体の数字と同じ形で比べられるかは分からない
- 同じ調査で、会社の情報などを公開AIツールに入れた、という申告は、禁止や方針がある職場のほうが多かった。ただし相関で、原因と結果は分からない
- 31の国・地域の企業調査（Microsoft・LinkedIn, 2024、査読なし）で、AIを使う人の78%が自分のAIツールを職場に持ち込んでいた。会社が認めている場合もあるので、「78%がルール違反」という意味ではない
- シャドーAI（会社が認めていないAIツールを使うこと）を、技術だけの問題ではなく、組織のルールや仕組み（ガバナンス）の問題として捉える研究がある（Silic ほか, 2025。確認できたのは抄録）
- 学習データの覚えやすさは、モデルの大きさ、同じ文章が学習データに出てくる回数、与える文脈の長さで増える傾向がある（Carlini ほか, 2023）
- 手指衛生のルールを守る割合は、12時間勤務の始めから終わりにかけて平均8.7ポイント下がると推定されていた（Dai ほか, 2015。アメリカの35病院・4,157人以上）。仕事が立て込んでいるほど下がり方が大きく、勤務の間の休みが長いと戻っていた。時間に追われることとセキュリティ行動のレビュー（Chowdhury ほか, 2019）は21本の研究を整理したもので、研究はまだ少ないとしている

### 分かっていないこと

- 人が会社のAIルールを確かめずに使う理由（知らない、面倒、聞きにくい、など）の割合。直接調べた査読済みの研究は見つかりませんでした
- 日本で「会社の情報を公開AIに入れた」人の割合（KPMGの日本版には載っていません）
- 会社の情報を公開AIに入れたことで、実際にどのくらい問題になったか
- 普段のチャットで入れた仕事の情報が、別の人への回答に出てくる確率
- 利用者がチャットに入れた内容が、学習を経て別の利用者に出てきたことを示した査読研究（今回は見つかりませんでした）
- 「学習に使わない」設定や法人向けのプランで、実際にどのくらいリスクが下がるか（第三者が確かめた研究は見つかりませんでした）
- 疲れや時間に追われることと、「AIに何を入れるか」の判断の関係
- この記事の3つの切り分けやチェックリストの効果（この記事の提案で、確かめられていません）
