# note記事づくりの共通ルール

すべてのエージェント（`.claude/agents/note-*.md`）と、まとめ役（`note-pipeline/PROMPT.md`）が従うルール。
Senaの事実・シリーズ・書き方が変わったら、ここだけを直す。

## 2. Senaについて（公開記事で確認できた事実のみ）

- 私立中高一貫校 → 単身でアメリカの大学へ進学。現地で半年働いた経験あり。
- 大学卒業後、GAFAMの1社に約5年勤務 → 2026年に別のGAFAMへ転職し、職種を変えてマーケティング職に。
- うつで精神障害者手帳を取得。大学時代に発症し、今も治療中。
- 社内の最新AIを仕事で使っている。
- ADHD：本人から「ADHDでもあり、知能検査を受けた経験も含めて記事にできる」と伝えられた（2026-10-02）。本人の立場は「ADHDでそれほど困っていない（部屋は片付けられないが、困ってはいない）」。企画に使ってよい。ただし公開記事で触れるまでは、具体的な体験・検査結果は【✏️要記入】で空ける。「困っていない」を他の当事者の困りごとを軽く扱う書き方にしない。
- PMDD：Senaが発信テーマとして挙げているが、公開記事ではまだ触れていない。扱う企画を出す場合は「本人の開示判断が必要」と明記する。
- 新しい公開記事で事実が増えていたら、それに従う。

## 3. 発信の軸

5領域：CAREER / WORK / AI / SELF・CONDITION / INTERSECTION。中心の視点は
「困難や特性があっても、どうやって自分のキャリアや人生をつくっていくか」。病気の解説メディアにはしない。

シリーズ（増やしてよい）：
- 「心の調子と働く」：SELF×WORK×AI
- 「外資テック解剖」：GAFAM2社比較を分解（評価基準、社内公募、フィードバック、意思決定など）
- 「AIに渡す仕事、渡さない仕事」：AI×WORK
- 番外：英語・アメリカの大学・グローバルキャリア

**バランスのルール**：直近3回の履歴と同じシリーズが3回続かないようにする。

## 4. テーマを1つ選ぶ

- 公開記事と `history.md` の両方と照合し、重複度を 🟢LOW / 🟡MEDIUM / 🔴HIGH で判定する。🔴は選ばない。🟡なら新しい切り口を明記する。
- 必要に応じて、査読済み研究・systematic review・meta-analysisを優先して調べる（WebSearch / WebFetch）。研究で分かっていること／Senaの経験／読者への問いを分ける。研究からSena個人の状態を推測しない。医学的な断定をしない。
- 「絶対バズる」などの断定はしない。流行だけで選ばない。

## 5. 記事ドラフトを書く

構成：研究上の論点 → 問題提起 → 私自身の経験 → 読者への問い・示唆。です・ます調、セクション区切りに「⸻」、見出しは「## 01｜…」形式。冒頭は「こんにちは、セナです。」。

**最重要ルール**：Senaが経験していないことを、Senaの経験として書かない。
- 公開記事で確認できた事実は書いてよい。
- それ以外の具体的な体験は **【✏️要記入：…】** として空け、ガイドの質問を添える。
- 研究の数値は出典を確認したものだけを使う。末尾に参考文献を列挙する。
- 医療・治療に触れる記事は、冒頭に「医療の記事ではない」旨の注意書きを入れる。

## 5.5 有料化の構成（2026-10-05〜。新しい下書きはこの構成で作る）

記事は「前半を無料、後半を有料」の構成にする。
- **無料部分**：冒頭のあいさつ、研究上の論点、問題提起。最後に「ここから先の有料部分で何が手に入るか」を1〜2文で示す。
- 無料と有料の境界に、単独の行で `【ここから有料】` を入れる（Senaがnoteの有料エリア設定の位置に使う）。
- **有料部分**：読んだあとすぐ使える実用的な中身にする。例：棚卸しシート／チェックリスト、質問例・声かけ例、手順（最初の1〜2週間など）、切り分けのフロー、研究で分かっていること・いないことの整理、参考文献。
- 有料部分の中身は「研究で分かっていること」と「私（Claude）の提案」を必ず分けて書く。提案は研究の結論のように書かない。期間や数字の区切りを入れる場合は「目安で、研究が示したものではない」と明記する。
- Senaが経験していないことは、有料部分でも【✏️要記入】で空ける。「Senaの記入例」「実際に試した感想」の欄を作ると、有料部分の価値になる。
- 価格は決めない（Senaが決める。既存の有料記事は200円）。公開用メモ（案）に「有料設定：【ここから有料】の位置で区切る」と書く。
- noteの表（`|` 区切り）は貼り付けても表にならないことがあるため、公開用メモに「表は箇条書きか画像に直す」と一言添える。
- 有料の既存記事と内容が重ならないよう、brief.md に重複の確認結果を書く（有料部分が読めない場合は「未確認」と書く）。


## 5.6 読まれる・買われる・反応がもらえる工夫（2026-10-08〜）

`analytics.md` の現状：コメントは全記事0、有料記事の購入は0件、「心の調子×働く」系がビュー・スキの中心。数字は小さく「兆し」として扱う。下の工夫はClaudeの仮説で、効果が確かめられたものではない。煽り・誇張・不安をあおる書き方はしない（「必読」「知らないと損」「絶対」など）。

**タイトルと冒頭**
- タイトルか副題に、読者が実際に検索しそうな言葉を入れる（例：「職種変更　最初の1ヶ月」「英語面接　自己紹介」）。
- 最初の3段落で「どんな場面で困っている人の記事か」を読者の言葉で書く。研究の話から始めない。
- 冒頭近くに「この記事で分かること」を3点まで箇条書きで置く（有料部分の中身も含めてよい）。

**無料部分（信頼をつくる）**
- 無料部分だけでも1つ持ち帰れるものを渡す（考え方の軸、最初の一歩など）。有料部分の出し惜しみのために無料部分を薄くしない。
- 無料部分の最後に「有料部分の目次」を箇条書きで具体的に示す（例：「・そのまま使える質問文10個 ・1週目／2週目のチェックリスト」）。何が入っているか分からないものは買われにくい。
- その直後に、押し付けない一言を置く（「ここまでで十分な人は、ここで閉じても大丈夫です」）。

**有料部分（買ってよかったと思える）**
- コピーしてそのまま使える形を最低1つ入れる：テンプレート、質問文・言い回し例、チェックリスト、記入シート、判断フロー。
- 「Senaの記入例」欄を【✏️要記入】で用意する（本人の実例が有料部分の価値になる）。
- 状況によって分かれる部分は「こういうときはA、こういうときはB」の分岐で書く。

**反応（スキ・コメント・フォロー）**
- 答えやすい問いを1つだけ、**無料部分の最後（有料部分の目次の直前）**に置く。有料記事の購入はまだ0件なので、本文の最後に置くと無料の読者には見えないため（選択式や「一言で」など。例：「あなたは①②③のどれに近いですか？コメントで番号だけでも教えてもらえたら嬉しいです」）。重い自己開示を求めない。
- マガジンへの案内とフォローのお願いは、コメントの問いのすぐ後（無料部分の最後）に1行ずつ、各1回だけ、控えめに。次回予告はシリーズ記事なら本文の最後に1行。
- 関連記事の案内（`## 次に読むなら`）は note-related-guide が入れる。

## 6. 保存先とファイルの形

フォルダ：`drafts/YYYY-MM-DD-am` または `drafts/YYYY-MM-DD-pm`（日本時間）。すでにあれば `-am2` `-pm2` のように番号を足す。

| ファイル | 書くエージェント | 中身 |
|---|---|---|
| `note-pipeline/theme-bank.md` | note-theme-researcher | 有料note向けテーマの在庫（15個ずつ追加。フォルダではなく note-pipeline に置く） |
| `status.md` | note-scout | 公開記事の一覧、反応データ、未仕上げ下書きの数、止めるべきかの判定 |
| `brief.md` | note-strategist | 選定理由（現在の記事数・反応データ、重複度と根拠、シリーズ上の位置づけ、研究との接点、タイトル案1つと型・強み）と、リサーチで確かめてほしい問い |
| `research.md` | note-researcher | 確認できた研究と数値（どこで確認したか付き）、分かっていないこと、使わないほうがよい情報 |
| `article.md` | note-writer | タイトル、本文、「公開用メモ（案）」、末尾に「仕上げに必要な質問」（要記入の一覧） |
| `related.md` | note-related-guide | 関連記事の案内（すすめる記事・次に困りそうなこと・つなぐ1行・誘導文）。案内文は article.md の最後にも入れ、`note-pipeline/related-map.md` に一覧を追記する |
| `review-facts.md` | note-fact-checker | 本文の数値・研究の説明が research.md と出典に合っているか |
| `review-voice.md` | note-editor | Senaの経験の捏造・開示・書式・有料構成のルールを守っているか |

- 公開用メモ（案）：ハッシュタグ5個（記事の種類・テーマ・シリーズ名を混ぜる）、検索を意識したタイトル案2つ（読者が実際に検索しそうな言葉を、タイトルか副題に入れる）、入れるマガジン（シリーズ名）、有料設定の一言。
- サムネイルは作らない（Senaが別のツールで作る）。
