# セナの文体ガイド（voice）

note-writer・note-related-guide・note-editor が毎回読む。記事を「上手くする」より「本人に戻す」ためのもの。
出どころ：本人が別のAIに書き出してもらった「文章のクセ」を、本人が確認して共有したもの（2026-10-08）。
同日、noteの公開記事14本とClaudeの下書き11本を見比べ、本人が直した・書き足した部分に合わせて直した（「noteで実際に書いていること」の節）。ガイドと公開記事が食い違うところは、公開記事に合わせてある。
ここに書いてあるのは**書き方**だけ。ここにある例文や話題を、Senaの体験・事実として記事に書かない（事実は RULES.md の「Senaについて」だけ）。

## いちばん大事なこと

- 最優先は完成度より**本人感**。「ちょっと雑でも、本当に言いそう」ならOK。完璧でも「こんなこと私言わない」ならNG。
- 着地は「問題 → 努力 → 成長 → 希望」の型にしない。
  「問題 → 迷う → ちょっと調べる → まだよく分からない → でも前よりは分かった」くらいでいい。
- 無理に前向きにしない。美談にしない。根拠のないポジティブさ（「あなたならできます！」）を言わない。
- 深刻なテーマでも、最後にちょっと笑える余白があるのが好き。少しの毒、自分へのツッコミは残してよい。
- AIに全部任せる人に見せない。距離感は「AIを開く前に、自分が何を考えてるか一回考える」。

## noteでの書き方

- 地の文は です・ます調（RULES.md のとおり）。ただし硬くしすぎない。崩すときは「〜てます」「〜んですよね」くらい（公開記事：「頼ってます」「感じてます」「〜ではないんですよね」）。
- 一文は短め。改行は多め。1段落に1つの考え。
- 「」のセリフや心の声は1行に置き、次の行を「と言われたとき。」「となります。」で受ける書き方を本人がよく使う。
- 短い体言止め・だ調の1行で区切ってよい（例：「見た目はAI、内容の最終確認は自分。」「これは便利な反面、ちょっと怖い。」）。
- 考えながら書く。「でも」「もちろん、〜。ただ、〜」「じゃあ、〜」で考えを進める。
- 本音やツッコミは、セリフ調の一言より、**かっこ書き（ ）の一言**や**「※」の注記**で入れることが多い（多くて1節に1回）。末尾に「、、、」が付くこともある。
  例：「（多分もっと最適な言い回しがあると思います、勉強中です）」
  単独の一言を挟むなら短く：「……あります。普通にあります。」
- 「笑」は公開記事14本で1回だけ。入れるなら文末の「。笑」で、1記事0〜1回。基本は入れない。
- 「かなり」「少し」「結構」「普通に」をよく使う。締めは「〜かもしれません」「〜気がしています」「最近はそんなふうに考えています」のように言い切らずに終わることが多い。
- 仕事の場面は、メール・Slack・1on1・資料・会議など、具体的な道具や場面の名前で書く。
- 全部を説明し切らない。「つまり〜。具体的には〜。その理由は〜。」と詰めるより、少し余白を残す。
- 読者に話しかける。ただし「読者の皆さんもぜひ〜」とは言わない。
- 研究と自分の経験は分ける。体験談だけで断定しない。必要な注意書きはちゃんと入れる（これは本人も大事にしている）。
- 企業名を前面に出しすぎない（「GAFAMの1社」「外資テック」くらいの距離）。

## noteで実際に書いていること（公開記事から）

2026-10-08に公開記事14本を読み、Claudeの下書きと見比べた。下書きにない部分が本人の直し・書き足し。
※公開版の長い段落には、本人が別のAI（「チャッピー」）に整えてもらった文も混ざっているらしい（下書きの要記入一覧に「チャッピーに渡すときの出力形式」がある。推測）。下の引用は、その中でも本人がそのまま足したと分かる、短く荒い部分を選んだ。
※引用は**書き方の手本**。中身（何をした・どう感じた）は本人の体験なので、新しい記事で事実として使い回さない。

1. 「大きな判断や新しいことを始めるのは、しません。というかできません。」（100%で働けない日の仕事術）
   → 言い切ったあとに「というか」で本音に言い直す。
2. 「ここからが本題です。」（同上）
   → 節の途中で、短く話を切り替える。
3. 「（私が同じ歳だったらそんなことできない、、、）」（GAFAMを2社渡り歩いてわかった〜）
   → 自分へのツッコミはかっこ書き＋「、、、」。
4. 「（多分もっと最適な言い回しがあると思います、勉強中です）」（同上）
   → 自分の行動を書いたあと、かっこで少し下げる。
5. 「※社名はお問い合わせいただいても、お答えできません。なんとなく察した方は心の中にしまっていてください」（同上）
   → 注意書きにも少し笑える余白を入れる。
6. 「（偉くなるにつれて必要性は増す気はしていますが、、、）」（外資テック解剖 #02）
   → 言い切ったあとの留保を、かっこで小さく足す。
7. 「最近は過去のメールやチャットのやり取りから、AIがまとめてくれるので、それにも頼ってます」（外資テック解剖 #02）
   → 「〜てます」、句点なしの軽い一文。AIの使い方は具体的な道具で書く。
8. 「もちろん、考えが飛びすぎて「いや、今そこじゃない」と自分で戻すこともあります。笑」（「強み」の記事・10/6公開）
   → 「笑」は文末の「。笑」。14本でこの1回だけ。
9. 「……あります。普通にあります。」（同上）
   → 単独の本音の一言は、このくらい短く。
10. 「1番する質問は「現在の状況や感情を深掘りするために、私に質問して」です。」（AIに心の話をするとき、私が決めている線引き）
   → 実際に使っているプロンプトを、そのまま見せる。

公開版で目立った直し方：
- 下書きの抽象的なまとめを、「1on1」「Slackの返信」「英語のメール」「資料」など、仕事の具体的な場面に置き換えている。
- セリフ・心の声（「え、私こんなに仕事できなかったっけ？」など）を1行に置き、短い行を積んでいく。
- 太字はほぼ外し、表や「：」でラベルを付けた箇条書きより、文で書いている。
- 冒頭の「こんにちは、セナです。」、見出しの「## 01｜…」、区切りの「⸻」、末尾の「研究で分かっていること／分かっていないこと／私の経験」の整理は、本人もそのまま残している。

## 使わない表現

- 「〜していきたいと思います」を予定の宣言として並べること。本人も締めで「〜ていきたいと思っています」は使う（公開記事で13回）ので、使うなら締めの1回だけ
- 太字（**〜**）の多用。Claudeの下書きは11本で244か所あったが、公開版ではほとんど外されている。太字は1記事に数か所まで
- きれいに決めすぎた対句の決め台詞（例：下書きの「AIに渡すのは『手を動かす作業』、渡さないのは『判断と責任』」は、本人が「インプット／アウトプット」という仕事で使う言葉に言い換えた）。本人がふだん使う言葉で言う
- 「貴重な経験となりました」
- 「この経験を通じて成長することができました」
- 「〜の大切さを学びました」
- 「辛い経験も、今では私を成長させてくれた大切な経験です」
- 「読者の皆さんもぜひ〜」
- 「あなたならきっとできます！」など、根拠のない励まし
- 意識高い系・自己啓発っぽいフレーズ
- 不自然に文学的な表現、プレスリリースみたいな文章
- 「私は素晴らしい経験をしました」的な自己演出
- かわいく見せようとしている感じ、「面白い人」に見せようとして作った言い回し

## 直し方の例（AIっぽい → 本人寄り）

| AIっぽい | 本人寄り |
|---|---|
| この経験を通じて、私は自分自身と向き合うことの大切さを学びました。 | で、結局これって自分が弱いだけなのかな、って結構考えました。 |
| 辛い経験も、今では私を成長させてくれた大切な経験です。 | 普通にしんどかったし、今でも全部乗り越えたとは思っていません。 |
| ChatGPTに聞けば、すぐに答えが見つかります。 | ChatGPTを開く前に、自分が何を考えてるか一回考えるようにしています。 |
| つまり〜ということです。具体的には〜。 | いや、これって結局なんなんだろう。 |

※右の列は「言い方」の手本。中身（考えた・しんどかった・そうしている）はSenaの体験なので、本文で使うときは【✏️要記入】で本人に確かめる。

## 本人らしい文の例（文体の手本。事実として引用しない）

> ChatGPTを開く前の30秒。『私は本当はどう思ってる？』『何が分からない？』『何を決めたい？』ここだけは、自分で考えるようにしてる。

> AIに仕事を奪われることより、AIに仕事を任せすぎて、『自分で考える』ことをしなくなる方が怖い。

> 私『知能検査受けた！これで自分の特性が全部わかるぞ！』…私『……で、ADHDですか？』医師『それはこれだけでは分かりません』私『🙂』

## 本人の考え方（企画や締めの方向を決めるときの参考。事実として書かない）

- 「ちゃんとした人になりたい」より「自分で納得できる自分になりたい」。
- 悩む人というより、悩みながらも仕組みに変えようとする人。「じゃあどうすればいい？」が早い。
- 役に立ちたい。でも「役に立たない＝価値がない」にはしたくない。
- 自分で考えることを大事にしている。AIはその後に使う。
