## 01｜直してもらった英語の「温度」を、自分で確かめにくい

日本語のメールなら、「ちょっと硬いな」「ここは言い方が強いかも」と、自分で気づける人が多いと思います。
英語だと、その感覚がかなり弱くなる人が多いと思います（私も、英語は今も勉強中です）。

つまり、AIが直してくれた英文が「正しいか」は、ある程度分かる。
でも、「この温度で相手に届くか」は、自分では判断しにくい。

これ、「AIに渡す仕事、渡さない仕事 #01」で書いた、「間違いに気づけるか」で渡すかを決める、という話と、たぶん同じ構造です。
間違いに気づきにくい部分ほど、AIに全部渡すと、あとで困る。

じゃあ、研究では、メールやチャットの「温度」とAIについて、何が分かっているのか。
少し調べてみました。

## 02｜研究で分かっていること・分かっていないこと

### 分かっていること

まず、AIの前の話。文字だけのやりとりで、温度感は伝わるのか。

アメリカの大学生を対象に、5つの実験を行った研究（Kruger ほか, 2005）があります。
皮肉か真面目かを、メールで読んだ側が当てられたかを見た実験（Study 2）では、声で聞いた側はほぼ4分の3を読み取れたのに対して、メールで読んだ側は、当てずっぽうと区別がつかない水準でした。
しかも、メールで送った側は、その差を予想できていませんでした。
別の実験（Study 3、154組）では、感情や口調を「伝えられる」と思っていた割合が平均89.3%（メール）で、実際に伝わったのは62.8%でした。
著者は、書いている本人には頭の中で口調が聞こえているので、読む側には聞こえないことに気づきにくい、と説明しています。
仕事のメールについて、受け取る側は書き手の意図より否定的か中立に読み違えやすい、と論じた理論の論文（Byron, 2008）もあります（こちらは実験ではなく、理論の整理です）。

次に、AIが入ったとき。

AIの返信候補（タップして送る短い返事）を使えるようにして、クラウドワーカー438人（219組）が約7分チャットした実験（Hohenstein ほか, 2023）では、こんな結果でした。

- 返信候補を使った人は、メッセージを速く送れた（1分あたり10.2%多い）。送ったメッセージの平均14.3%が返信候補だった
- 会話の感情の向きは、返信候補の向きに寄った（ネガティブな候補があった会話は、ポジティブな候補やGoogleの候補の会話より、否定的な内容が多かった）
- 相手が返信候補を多く使うほど、相手は「協力的」「親しみがある」と評価された
- 一方で、「相手は返信候補を使っていそうだ」と思うほど、相手は協力的でない、親しみが低いと評価された（実際の使用量をそろえても。相関です）

つまり、AIを使うと感情の温度が動いて、評価も上がりうる。でも、AIを使っていると「思われる」と、見られ方は下がりうる、という実験です。

文体の話もあります。
日本人とアメリカ人の参加者が、職場のメールを母語で書く実験（Sakai ほか, 2026）では、日本の参加者のほうが、丁寧さやお詫びの表現が有意に多く、AIの下書きを見せると、メールは下書きの文体の側に動きました。下書きが自分の文化の文体とずれているほど、動きは大きく、日本の参加者は「直接的な下書き」で最も動いた、という結果です。（これは査読前のプレプリントです）

最後に、英語が母語でない書き手の話。

英語が母語でない大学生が、英語で教員に送ったお願いのメールを調べた研究（Economidou-Kogetsidis, 2011）では、かなり直接的で、和らげる言い回しや挨拶・結びが抜けているメールがありました。著者は、そういうメールは失礼に読まれうる、と論じています（相手に断る余地を与えず、負担をかけることへの配慮が見えないため）。
また、英語母語話者と、英語力が限られた話者の32組が共同で文章を書いた実験（Xiao ほか, 2024）では、AIの編集ツールがあっても、母語でない話者は不利から抜けられませんでした。AIで整った文を見た母語話者が、相手の英語力や文章への貢献を、実際より高く見積もってしまい、共同作業に緊張が生まれた、とされています。
さらに、昇進のお願いの文を（仮想の場面で）AIの自動補完を使って書く実験（Kadoma ほか, 2024）では、AIの提案をたくさん受け入れるほど、コントロールや主体感が下がりやすい傾向がありました。ただ、その場に「含まれている」感覚が高い人では、下がり方が弱まっていました。

### 分かっていないこと・注意点

- Kruger ほかは、アメリカの大学生が英語で、皮肉などを送り合った実験です。職場のSlackで同じ割合になるとは言えません。2005年の研究で、絵文字やスタンプのある今のチャットとは違います
- Hohenstein ほかは、知らない人どうしの短いチャットで、AIも「返信候補」です。英文を丸ごと直してもらう使い方とは違います。日本の職場でも同じとは限りません
- Sakai ほかは査読前で、母語で書いたメールです。日本人が英語で書くときに、同じことが起きるかは、この研究だけでは分かりません
- Economidou-Kogetsidis は、キプロスの学生から教員へのメールです。日本人の書き手や、今のSlackの文体の研究ではありません。Xiao ほかも共同執筆の実験で、職場のやりとりではありません
- 日本人が英語のSlackやメールをAIに直してもらったときに、相手からどう読まれるかを直接調べた研究は、今回調べた範囲では見つかりませんでした
- 「温度感を先に決めてからAIに頼むと、温度が残る」ことを確かめた研究も、見つかりませんでした。後半の頼み方は、そこの提案です

まとめると、

- 文字だけの温度感は、書いた人が思うほど伝わらない。実験では、書いた側はそれに気づきにくかった
- AIは、感情の温度や文体を、AIの側に寄せることがある。使う人の見られ方も動く
- 英語が母語でない書き手の英文は、直接的すぎると失礼に読まれうる。AIで整えると、読む側が実際より上手だと思うことがある
- でも、「日本人が英語のSlackをAIに直す」ときに何が起きるかは、まだ分からない

という感じでした。

なので、この記事では「AIに直してもらえば、英語の返信は大丈夫」とも、「AIを使うと自分の言葉が消える」とも言いません。
言えるのは、温度感は自分が思うほど伝わらないこと、AIの文は自分の温度とずれうること、くらいです。

## 03｜無料で持ち帰れる軸：AIに貼る前に、温度感を3つだけ決める

ここからは研究の結論ではなく、この記事の提案です。

英語の温度感を、英語のまま判断するのは難しい。
なら、AIに貼る前に、日本語で、この3つだけ決めます。

1. 相手は誰？（上司・同僚・他部署・社外。距離はどれくらい？）
2. 今回は何をしたい？（お願い・断り・催促・お礼・お詫び・報告のどれ？）
3. 残したい温度は？（「短く」「やわらかく」「はっきり」から1つだけ）

たとえば「同僚に、返事が来ていない件を催促する。やわらかく」。
これを決めてから貼ると、直ってきた英文が「やわらかい催促」になっているかを、照らし合わせられます。
決めないまま貼ると、AIの出した温度が、そのまま自分の温度になってしまうかもしれません。（Hohenstein ほかの、感情の向きがAIの候補に寄った結果を見て、そう考えました）
（例は読者の場面として書いたもので、私の状況ではありません）

温度を3つ決められないときは、AIに「私に質問して」と頼んで、聞いてもらうのも手です。
私がAIによく頼むのは「私に質問して」で、理由は、自分で分かっているつもりのことも、「なんで？」と聞かれると意外に答えられないからです。
温度感も、たぶん同じです。

ひとつだけ、聞かせてください。

英語の返信をAIに直してもらったとき、あなたは ①ほぼそのまま送る ②一部だけ使う ③見るだけで自分で書き直す のどれに近いですか？ コメントで番号だけでも教えてもらえたら嬉しいです。

「AIに渡す仕事、渡さない仕事」は、マガジンにまとめています。
続きを読みたい方は、フォローしてもらえると励みになります。

## 05｜AIへの頼み方5つ（コピー用）

以下はこの記事の提案です。研究で効果が確かめられた頼み方ではありません。
〔 〕の中は、自分の状況に置きかえてください。
全部やらなくて大丈夫です。1だけ、1と2だけでも使えます。

頼み方1：3点セットを先に渡す

```
英語のSlack（またはメール）の返信を直してほしいです。
相手：〔上司／同僚／他部署／社外〕
目的：〔お願い／断り／催促／お礼／お詫び／報告〕
残したい温度：〔短く／やわらかく／はっきり　のうち1つ〕
言いたいこと（日本語）：〔一言で〕

下の私の英文を、この条件で直してください。
意味は変えず、内容を足したり削ったりしないでください。

〔自分で書いた英文〕
```

「内容を足したり削ったりしないで」を入れるのは、AIが親切に、お礼やお詫びの一文を足すことがあるからです。

頼み方2：直すだけ（変えた所を教えてもらう）

```
直した所だけ、元の英文と並べて見せてください。
変えた理由を、日本語で1行ずつ書いてください。
丁寧さや感情の強さ（Thanks! などの感嘆符、"so much"、謝り方、強い言い切り）が変わった所には、「温度が変わった」と印をつけてください。
```

英語が全部は読めなくても、「温度が変わった」の印のところだけ見ればいいので、確かめやすくなります。

頼み方3：自分の文の特徴を残す

```
以下は、私が過去に実際に送った英語のSlackとメールです（宛先・社名・固有名詞は〔 〕に置きかえ済みです）。
私の書き方の特徴（文の長さ、よく使う言い回し、挨拶の有無、丁寧さの度合い）を、日本語で5つ以内にまとめてください。
次からは、その特徴を残したまま直してください。

〔過去の英文を2〜3通〕
```

ここは、社内の情報が入りやすいところです。会社のルールを確認して、固有名詞は必ず置きかえてから貼ってください（07のチェックリストも見てください）。

頼み方4：温度違いで3案

```
同じ内容を、温度の違う3案にしてください。
A：いちばん短く
B：少しやわらかく
C：丁寧で、少し長め
それぞれ、相手にどう読まれそうかを、日本語で1行で添えてください。
```

選ぶのは自分。3案を並べると、「自分は今、どの温度がいいか」が、逆に見えやすくなります。

頼み方5：相手の読み方を日本語で確認

```
この英文を、〔相手〕が受け取ったとき、どう読みそうですか？
「冷たい」「強い」「丁寧すぎる」「よそよそしい」と感じる可能性があれば、その理由を日本語で教えてください。
「大丈夫です」で終わらせず、気になる点を最低1つ挙げてください。
```

最後の1行は、AIが「問題ありません」で終わらせるのを防ぐためです。
ただ、AIの答えも推測です。相手のことをいちばん知っているのは、相手との過去のやりとりなので、迷ったら、相手が前に送ってくれた1通を見るほうが確かです。

## 06｜場面別の分岐と、英語の言い回し例

ここも、研究が直接示したものではなく、この記事の提案です。
英語の例は、温度の違いが分かりやすいように作った一例で、会社・国・相手との距離で合う温度は変わります。

お願いするとき
→ 断る余地を残して、負担を減らす一文を足す（Economidou-Kogetsidis の、直接的すぎるお願いが失礼に読まれうる、という話から考えました）。

- 直接的：Send me the file by tomorrow.
- やわらかく：Could you send me the file by tomorrow? If that's tight, let me know and we can adjust.

催促するとき
→ 「責めていない」ことと、「何がほしいか」を両方入れる。

- 短く：Any update on this?
- やわらかく：Just checking in on this. Could you share a quick update by Thursday? No worries if it's still in progress.

断るとき
→ 断る理由を長く書くより、代わりに何ができるかを1つ添える。

- はっきり：I can't take this on this week. I could look at it next Tuesday if that works.
- やわらかく：Thanks for thinking of me. I can't take this on this week, but I could look at it next Tuesday if that works.

お礼を言うとき（Slack）
→ 短い返事に、感嘆符と "so much" を重ねすぎない。AIは、ここを盛りやすいかもしれません（確かめていない予想です）。

- 短く：Thanks, that helps.
- 少し温かく：Thanks, that helps a lot!

お詫びするとき（遅れた）
→ 謝りは1回。そのあと、いつ出すかを書く。

- Sorry for the delay on this. I'll send it over by end of day.

調子が低い日（返信が重い日）
→ 長い文を書かずに、「見た」と「いつ返すか」だけ送る。ここだけは、AIに頼まず、自分の定型を持っておくのも一つです。

- Got it. I'll take a look this afternoon.
- I'll reply properly by tomorrow morning.

（どこまで事情を書くかは、「職場に、心の調子をどこまで伝える？」の話になります。ここでは触れません）

Slackとメールの違い
→ Slackは短く、メールは挨拶と結びを入れる、くらいで考える。AIは、Slackにもメールのような挨拶を足すことがあるので、「Slackなので短く」と頼み方1の3点セットに入れておく。

## 07｜AIに渡す前・渡したあとのチェックリスト

以下はこの記事の提案で、会社の規程や法律の判断ではありません。

```
渡す前
□ 会社のAIか、個人のAIか（会社のルールで、入れていい情報が違う）
□ 社名・顧客名・プロダクト名・同僚の名前・金額は、入れない、または〔顧客A〕などに置きかえる
□ 3点セット（相手・目的・残したい温度）を決めた
□ 自分で書いた英文か、日本語のメモを先に作った

渡したあと
□ 意味が変わっていない（日付・数字・誰が何をするか）
□ お願いが命令に、確認が依頼に変わっていない
□ 感嘆符（!）、"so much"、"really appreciate" など、温度を上げる言葉が増えていない
□ 謝り（sorry）が増えていない。または、必要な謝りが消えていない
□ 相手が普段使う言い回しとかけ離れていない（相手の過去の1通を見た）
□ 自分が普段使わない言い回しは、自分の言葉に戻すか、「これは覚えよう」と決めた
□ 送る前に、自分でもう一度読んだ
```

いちばん大事なのは、最後の1つかもしれません。
AIに出してもらうのは候補まで。送るかどうかを決めるのは自分。

それと、AIを使うこと自体は、悪いことではないと思っています。
ただ、Hohenstein ほかの実験では、「AIを使っていそう」と思われると見られ方が下がる傾向がありました。
全部を自分で書く必要はないけれど、一文でも自分の言葉を残しておくと、「誰の文か」が自分でも分かりやすい気がします。（これは私の考えで、研究の結論ではありません）

## おわりに
