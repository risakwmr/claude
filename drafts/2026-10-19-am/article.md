## 02｜研究で分かっていること：「分からないまま使う」は少なくない

KPMGとメルボルン大学が、47か国・48,340人に行ったオンライン調査があります（2024年11月〜2025年1月）。
大学の研究チームが設計した大きな調査ですが、査読を受けた論文ではなく、調査報告です。
そのうち、働いている人が職場のAIについての質問に答えています。

職場でAIを使っている人（47か国全体）のうち、

- 「許されているか分からないまま、職場でAIツールを使った」：56%
- 「会社の情報（財務・営業・顧客情報など）を公開AIツールにアップロードした」：48%

と答えていました。

ここは誤解しやすいので、先に断っておきます。
この割合は「少なくとも一度はある」という意味で、「まれに（Rarely）」と答えた人も含まれています。
たとえば48%は、「まれに」14%と「ときどき〜とてもよく」34%を足した値です。
「半分の人が日常的に会社の情報を入れている」という意味ではありません。
「会社の情報」がどのくらい機密のものかも、この調査では分かりません。

もう1つ。
勤め先に生成AIの方針やガイダンスがあると答えた人は、禁止の方針も含めて約4割でした。
19%は、方針があるかどうか「分からない」と答えています。

日本の数字もあって、日本版の資料では「方針やガイドラインに反する使い方をした」が37%でした。
ただ、日本版の資料には、分母（誰の中の37%か）や集計のしかたが書かれていません。全体の数字と同じ形で比べられるかは、分かりません。

どれも本人の申告で、実際の行動を見たものではありません。
報告書自身も、言いにくい行動なので少なめに出ている可能性がある、と書いています。

### 聞きにくさも、あるのかもしれない

もう1つ、気になった研究があります。

アメリカで行われた4つの実験（合計4,439人、PNAS）で、仕事でAIを使う人は「能力ややる気を低く見られる」と予想していて、実際にそう評価されていました。
1つ目の実験では、AIツールを使う場面を想像した人のほうが、そうでないツールの場面の人より、上司や同僚に使ったことを伝えたがらない傾向がありました。

これは「使ったことを伝えるか」の実験で、「ルールを聞くか」を調べたものではありません。
なので、ここからは推測です。
「AI使ってるって言いにくい」が、「これ入れていいですか、と聞きにくい」の背景の1つになっているのかもしれません。

（人がルールを確かめずに使う理由を、直接調べた査読済みの研究は、今回は見つかりませんでした）

## 03｜「入れたら漏れる」は、どこまで分かっているか

ここで、不安になりすぎないために、技術の研究も少しだけ。

大規模言語モデル（ChatGPTのようなAIの中身）は、学習に使われた文章の一部をそのまま覚えていて、条件がそろうと出してしまうことがある。
これは研究で確かめられています。

- 古いモデル（GPT-2）から、学習データの文章を数百件、一字一句そのまま取り出せた研究がある（Carlini ほか, 2021）
- 一般向けの対話型AI（ChatGPTを含む）からも、数千件の学習データを取り出せた研究がある（Nasr ほか, 2025）

ただ、ここからが大事なところです。

- これは、研究者が意図的に工夫した入力で「攻撃した場合」の結果です
- 取り出されたのは、主に公開ウェブ由来の学習データで、ほかの利用者がチャットに入力した内容が出てきたわけではありません
- 対象のモデルは古いものが多く、事業者はその後対策をしています
- 「一字一句覚えている」ことと「チャットで漏れる」ことは同じではない、という研究もあります（Sander ほか, 2025）

なので、普段のチャットで入れた内容が、別の人の画面に出てくる確率は、分かっていません。
「入れたら漏れる」とも、「入れても漏れない」とも言えない。

一方で、利用者側の研究では、人と話しているような会話のスタイルが、より踏み込んだ打ち明け話を促していた、という結果もありました（Zhang ほか, 2024。会話データの分析と19人へのインタビュー）。

話しやすいから、つい入れてしまう。
これは、ちょっと分かる気がします。

もう1つ。
入れたものは、学習に使われるかどうかとは別に、サービス側に保存されます。
なので「学習に使わない設定なら、何を入れても大丈夫」とも言えません。
どのAIで、どういう契約・設定になっているかは、サービスや会社によって違いますし、変わりやすいところです。ここは会社が用意した説明や、サービスのページで確認してください。

## 04｜「どの情報ならいいか」は、研究ではなく会社のルールで決まる

じゃあ、国のガイドラインはどうなっているのか。

総務省・経済産業省の「AI事業者ガイドライン（第1.2版、2026年3月）」には、AIを使う側について「機密情報等を不適切に入力することがないよう注意を払う」「個人情報を不適切に入力することがないよう注意を払う」といった項目があります。
個人情報保護委員会も2023年6月に、生成AIサービスに個人情報を入れるときの注意を出しています。

ただ、このガイドラインは罰則のない「ソフトロー」で、宛先は従業員一人ひとりではなく、事業者（会社や、会社の中の部門）です。
そして別添では、各社が自分たちのAIポリシーや規定に合ったチェックリストを作ることや、悩みを抱え込まずに相談できる体制をつくることが大事だ、と書かれています。

つまり、「この情報は入れてよい／いけない」という具体的な線は、国が一律に決めているのではなく、各社がルールとして決める形になっている。
外資系の会社なら、本社の方針や海外の法令も関わってくるはずです。

だから、個人の感覚で決めるより、まず会社のルールを確認する。
当たり前と言えば当たり前なんですが、、、

でも、実際は02のとおり、ルールがあるか分からない人が少なくない。
ルールがあっても、目の前のこの資料が「どれ」に当たるのか、すぐには分からない。

それで、毎回「たぶん大丈夫」を自分の感覚で決めることになる。

これだと、迷いは毎回ゼロからやり直しです。
しかも、もし間違えたときに、自分一人で決めたことになってしまう。

じゃあ、どうするか。
「自分で決めない」ことを、手順にしてしまう。今回の記事は、その話です。

## 05｜無料で持ち帰れる軸：3つで切り分ける

ここからは研究の結論ではなく、この記事の提案です。
この切り分けで間違いが減ることを確かめた研究はありません。また、会社のルールがあれば、そちらが優先です。

入れる前に、次の3つを順番に見ます。

1. 会社のルールはある？（ある／ない・分からない）
2. どのAI？（会社が用意したAI／個人で使っている外部のAI）
3. 何の情報？（もう公開されている／社内限り／顧客・個人・未発表）

見る順番は、1→2→3です。

1で「分からない」なら、その時点で入れずに、確かめる側に回る。
1で「ある」なら、2と3をルールに照らす。
ルールを読んでも自分の情報がどれに当たるか分からなければ、それも「分からない」として、聞く。

たとえば、

もう社外に公開されている資料の要約を、会社が用意したAIで頼む
→ ルールで認められているなら、迷う場面は少なめ。

まだ発表していない数字が入った資料を、個人で使っているAIに貼る
→ 3つとも慎重な側。ここは入れずに、聞く。

という感じです。
（例は読者向けに作ったもので、私の実際の仕事ではありません）

ポイントは、「入れていいか」を自分で決めるのをやめて、「分からなかったら聞く」までを手順に入れておくこと。
迷うのが悪いのではなくて、迷ったときの行き先を先に決めておく、くらいの感じです。

ひとつだけ、聞かせてください。

AIに入れる前に手が止まるのは、①社内の資料 ②顧客や数字 ③同僚の名前や評価 のどれが多いですか？ コメントで番号だけでも教えてもらえたら嬉しいです。

「AIに渡す仕事、渡さない仕事」は、マガジンにまとめています。
続きを読みたい方は、フォローしてもらえると励みになります。

## 07｜コピー用：AIに入れる前のチェックリスト

以下はこの記事の提案です。

```

## 08｜切り分けのフロー

ここもこの記事の提案です。研究が示した手順ではありません。

会社のルールがあるか

- 分からない → 入れない。まずルールがあるか聞く（09の質問文A）
- ない（と確認できた） → 「ないから自由」ではなく、上司か担当部署に「どう扱えばいいか」を聞く（質問文B）。返事が来るまでは、公開済みの情報だけにする
- ある → 次へ

どのAIか

- 会社が用意したAI → ルールで、どの情報まで入れてよいとされているかを見る
- 個人で使っている外部のAI → ルールで仕事に使ってよいとされているかを先に見る。書かれていなければ、聞く（質問文C）

何の情報か

- もう公開されている → ルールの範囲なら、迷う場面は少なめ
- 社内限り → ルールで認められているAIと範囲だけ
- 顧客・個人・未発表 → ルールではっきり認められている場合だけ。少しでも迷ったら、入れずに聞く

どこかで「分からない」が出たら、その先には進まない。
フローの役目は、「入れていいか」を決めることより、「聞く地点」を見つけることです。

## 09｜コピー用：上司・担当部署に聞くときの質問文

〔 〕の中は自分の状況に置きかえてください。

質問文A：ルールがあるか分からないとき（日本語・上司やチームに）

```

質問文C：具体的な情報とツールで聞くとき（日本語）

```
〔会社が用意したAI／個人で契約しているAI〕に、
〔社内向けの議事録／まだ公開していない数字が入った資料〕を入れて、

```

```

```

```

```

（英語は、多分もっと自然な言い回しがあると思います、、、相手との距離に合わせて直してください）

聞くのが気まずいときは、「自分が使っていいか」より「チームとしてどう扱うか」の聞き方にすると、少し聞きやすいかもしれません。
02の研究のとおり、AIを使っていることを言いにくい感覚はあるようなので。これは推測です。

## 10｜名前や数字を伏せる・置き換える手順

最初に。
伏せればAIに入れてよい、という話ではありません。伏せた場合の扱いも、会社のルールが優先です。ルールで認められていない情報は、伏せても入れないでください。

そのうえで、ルールの範囲で使うときの提案です（研究で効果が確かめられた手順ではありません）。

手順

1. 人の名前 → 〔Aさん〕〔Bさん〕に置き換える
2. 会社名・取引先名 → 〔取引先1〕〔取引先2〕に置き換える
3. 製品名・プロジェクト名 → 〔製品X〕〔プロジェクトY〕に置き換える
4. 数字 → 頼みたいことに数字が要らなければ消す。要るなら〔100〕のような仮の数字にする
5. 日付 → 〔来週〕〔月末〕のように、ぼかす
6. 置き換えたあとに、全文を一度読み返す。読んだ人が「どこの会社の、何の話か」分かってしまわないか

置き換えても入れないほうがよい情報（この記事の提案）

- 組み合わせると特定できるもの（業界・時期・規模がそろうと、名前を伏せても分かってしまう）
- 人事評価、健康のこと、家族のことなど、その人に関わる話。名前を伏せても、本人が読めば分かることがある
- 契約などで、外に出さないことになっている情報（自分で判断がつかなければ、聞く）
- 自分で「これは出したらまずい」と少しでも感じるもの

AIに頼むときの書き方（例）

```
以下は、名前と数字を置き換えた社内向けのメモです。
〔Aさん〕〔取引先1〕などは仮の名前です。本当の名前を推測しようとしないでください。
このメモを、3行で要約してください。
```

置き換えるのは、正直ちょっと面倒です。
でも、その面倒くささが「本当にこれ、AIに頼む必要ある？」を考える時間にもなる気がしています。

## 11｜分岐：急いでいる日・調子が低い日

私はうつで治療中で、100%で働けない日があります（「100%で働けない日の仕事術」に書きました）。
なので、この分岐も入れておきます。

研究で分かっていること（別の分野の研究です）

- アメリカの35病院・4,157人以上の医療スタッフのデータで、手指衛生のルールを守る割合は、12時間勤務の始めから終わりにかけて平均8.7ポイント下がっていました（Dai ほか, 2015）。仕事が立て込んでいるほど下がり方が大きく、勤務の間の休みが長いと、次の勤務で戻っていました
- 時間に追われることとセキュリティ行動の関係を、21本の研究から整理したレビューでは、時間に追われると負担やストレスが増え、行動に悪い影響が出うるとされています。ただ、研究はまだ少ないとも書かれています（Chowdhury ほか, 2019）

どちらも、オフィスワークやAIへの入力を調べたものではありません。
そして、研究が見ているのは「長く働いた・時間に追われた」で、うつや体調の波のある「調子が低い日」を調べたものではありません。
言えるのは、「疲れていると、分かっているルールでも守りにくくなる傾向が、別の分野で報告されている」くらいです。

そのうえでの、この記事の提案です（目安で、研究が示したものではありません）。

- 急いでいる日 → 07のチェックリストを全部見ようとせず、【1】ルールと【2】どのAIかだけ見る。どちらかが分からなければ、今日はAIに入れずに自分でやるか、後回しにする
- 調子が低い日 → 「迷ったら入れない」を初期値にする。公開済みの情報だけでできる頼み方に切り替える（たとえば、資料は貼らずに「こういう構成の資料の、見出しの案を出して」と頼む）
- 調子が低い日に聞く必要が出たとき → その場で質問文を考えず、09の文例をそのまま貼る。返事待ちのあいだは、入れない
- 調子が良い日 → 05の3つどおりで大丈夫。ただ、慣れていても「たぶん大丈夫」は出てくるので、07の最後の1行は残す

【✏️要記入：調子が低い日や急いでいる日に、AIの使い方を変えているか。（ガイド：「低い日は新しい資料をAIに入れない」「低い日はそもそもAIを開かない」など、変えていることがあれば。特に変えていなければ「変えていない」でも大丈夫です。社内ルールの内容は書かない）】

## 12｜入れてしまったと気づいたら

ここは法律の判断ではなく、気づいたあとの動き方の提案です。会社に決まった手順があれば、そちらに従ってください。

1. それ以上、入れない（続けて同じ会話に貼らない）
2. 何を・いつ・どのAIに入れたかを、自分用にメモする（入れた情報そのものを、別の場所にまたコピーしない）
3. 会話の履歴を消すかどうかは、自分で決める前に聞く（消してよいか、残しておくべきかは会社の手順による）
4. 上司か、会社の情報管理の窓口に、早めに伝える
5. 一人で「たぶん大丈夫だった」と片付けない

一人で抱えないこと。
04で書いたとおり、ガイドラインでも「悩みを抱え込まずに相談できる体制」が大事だとされていて、そのための窓口のはずなので。

一報の文例（日本語・上司や窓口に）

```
ご相談です。
本日〔時間〕ごろ、〔AIツールの種類：会社のAI／個人のAI〕に、
〔情報の種類：社内向けの資料の一部／顧客名を含むメモ〕を入力してしまいました。
入力したのは〔範囲：1ページ分／数行〕です。
このあとどう対応すればよいか、指示をいただけますか。
```

英語（Slackで）

```
Hi 〔Name〕, I need to flag something.
Earlier today I put 〔type of information〕 into 〔type of AI tool〕 by mistake.
It was about 〔scope〕. What should I do next?
```

気づいて言えるのは、むしろちゃんとしている側だと思います。
言い訳を長くするより、何を・どこに・どのくらい、を先に伝えるほうが、相手も動きやすいはずです。

## 13｜研究で分かっていること・分かっていないこと

### 分かっていること

- 47か国の調査（KPMG・メルボルン大学、2024年11月〜2025年1月、査読なし）で、職場でAIを使っている人のうち、「許されているか分からないまま職場でAIツールを使った」56%、「会社の情報を公開AIツールにアップロードした」48%、「方針・ガイドラインに反する使い方をした」44%（いずれも「まれに」を含む、47か国全体）
- 同じ調査で、勤め先に生成AIの方針（禁止を含む）があると答えたのは約4割、19%は「分からない」。日本版の資料では「方針に反する使い方をした」37%（分母の記載なし）
- 同じ調査で、禁止や方針がある職場のほうが、こうした行動の申告が多かった。ただし相関で、原因と結果は分からない
- 31の国・地域の企業調査（Microsoft・LinkedIn, 2024、査読なし）で、AIを使う人の78%が自分のAIツールを職場に持ち込んでいた。ただし、会社が認めている場合もあるので、「78%がルール違反」という意味ではない
- 仕事でAIを使うと低く評価されると予想し、実際にそう評価される、という実験がある（Reif ほか, 2025）
- シャドーAI（会社が認めていないAIツールを使うこと）を、個人の問題より組織の仕組みの問題として捉える研究がある（Silic ほか, 2025。確認できたのは抄録）
- 学習に使われた文章が、研究者が意図的に攻撃した場合に、そのまま取り出せることがある（Carlini ほか, 2021／Nasr ほか, 2025）。覚えやすさは、モデルの大きさ、同じ文章の重複の回数、与える文脈の長さで増える傾向がある（Carlini ほか, 2023）
- 一字一句覚えていることと、チャットで漏れることは同じではない（Sander ほか, 2025）
- 人と話すような会話のスタイルが、踏み込んだ打ち明け話を促していた（Zhang ほか, 2024）
- 日本の公的な文書（AI事業者ガイドライン第1.2版、個人情報保護委員会の注意喚起）は、入力する情報に注意することを求めていて、具体的な線引きは各社のルールに委ねる形になっている。AI事業者ガイドラインは事業者向けのソフトロー
- 別の分野だが、長く働いて疲れると、分かっているルールでも守りにくくなる傾向が報告されている（Dai ほか, 2015）

### 分かっていないこと

- 人が会社のAIルールを確かめずに使う理由（知らない、面倒、聞きにくい、など）の割合。直接調べた査読済みの研究は見つかりませんでした
- 日本で「会社の情報を公開AIに入れた」人の割合（KPMGの日本版には載っていません）
- 会社の情報を公開AIに入れたことで、実際にどのくらい問題になったか
- 普段のチャットで入れた仕事の情報が、別の人への回答に出てくる確率
- 利用者がチャットに入れた内容が、学習を経て別の利用者に出てきたことを示した査読研究（今回は見つかりませんでした）
- 「学習に使わない」設定や法人向けのプランで、実際にどのくらいリスクが下がるか（第三者が確かめた研究は見つかりませんでした）
- 疲れや時間に追われることと、「AIに何を入れるか」の判断の関係
- この記事の3つの切り分けやチェックリストの効果（この記事の提案で、確かめられていません）
